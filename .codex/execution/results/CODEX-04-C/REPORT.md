### Encrypted private payload convention

The exact journal fact fields are the ones required by the staged transport. The journal validates bounded JSON, not service command schemas. Stage 2 must define and strictly validate its own `command`, `result` and `effect` schemas, retaining this storage convention:

- `command` is the exact normalized authorized service command, including its private payload. `result` is the committed logical result before an external durability acknowledgement is attached. AcceptRequest's outward acknowledged result must remain EXACT common wire 1.1.0; never expose the internal fact as its result.
- `effect.snapshot` holds the complete private current queue projection, including interpretation, clarification/answer, alternative, fit evidence, agreement provenance, revised estimate and late support DRAFT. `effect.history` holds this command's attributed history entry, actual server timestamp and states. Both are read through the owning authenticated fact.
- `effect.scopes` is an object keyed by decimal queue scope_version, containing any scope versions introduced by this command. Each stores original/correction/alternative question/context, explicit source kind and predecessor lineage. queue_scopes.payload_ref resolves the command fact and then effect.scopes[String(scope_version)]. No private text is duplicated into SQL metadata.
- Global intake command/result/reason and complete intake snapshot reside in the operator fact, with `effect.intake` containing the committed intake projection. queue_operator_commands.paused must equal that authenticated projection. No household question/context belongs in an operator fact.

The recursive journal limits are implementation bounds for local serialization, not production offer/policy defaults: 4096 total JSON nodes across command/result/effect; depth 8 per root; 1024 array elements; 256 object fields; 200 UTF-16 units per member name; 16000 units per string; 60000 UTF-8 bytes for the three private objects together and 70000 for the whole fact. Service schemas must fit these bounds; reject oversized input before primary mutation. Do not accumulate unbounded full history in every snapshot: immutable per-command history can be read from its own facts with bounded pagination. The service must bound its own projection and scope payloads before sealing.

## Journal behavior and limits

`createSyntheticQueueJournal({env,directory,keys,testHooks?})` accepts EXACT key methods keyForHousehold and keyForOperator. It exports namespace_verifier and seal, append, records, fact, close. The namespace derives from a persisted random manifest, remaining stable across restart. AES-256-GCM binds the safe envelope header as AAD; separate HMAC-derived household/operator encryption and frame-authentication domains include that namespace. Operator material never calls the household method. Trusted callbacks must return separate, stable 32-byte fixture keys; no key, credential or private payload is logged or written as metadata.

Facts enforce exact fields; canonical millisecond UTC timestamps; UUID identities; positive safe aggregate/household epoch or operator epoch 0; founder-only operator actors; hex64 digests/session hashes/namespace; plain bounded command/result/effect objects. Descriptor validation rejects proxies, getters, extra fact fields, inherited custom prototypes, sparse/extended arrays, cycles, nonfinite values and unsafe JSON member names. Decryption uses duplicate-rejecting strict JSON parsing and canonical-byte equality. Public HTTP duplicate rejection remains the later host's responsibility.

Append verifies the actual encrypted committed fact, serializes operations, checks the entire existing authenticated chain, writes every frame byte, fsyncs, reopens and reauthenticates before returning queue-fsync:<record_id>. A repeated identical fact returns its original reference once, including an exact fact resealed with a fresh random nonce. Changed fact under the same scope/command identity returns typed conflict, without appending. Reused record or scoped commit identity also conflicts. beforeAppend receives only a cloned encrypted envelope; hook failure writes nothing. Quarantine errors have generic messages without private contents.

Startup authenticates/decrypts every stored frame. Wrong household/operator key, malformed UTF-8, bad manifest, frame corruption, partial tail, namespace mismatch or failed authenticated reopen quarantines without truncation, rewrite, repair or rename. Quarantine is a failure state; recovery requires separately authorized investigation. An existing empty file is invalid rather than silently treated as new history. Limits: 16 MiB file, 10000 facts, 140000 bytes per frame. Hitting a bound closes new appends rather than pruning history.

The directory must preexist, be absolute/canonical and contain no symlink ancestor. File checks reject symlinks/hard links and compare device/inode on repeated reopen. POSIX UID/mode checks apply; Windows ACL ownership remains an explicit setup prerequisite, as in accepted local primitives. In-process directory ownership is released only by the owning initialization or close, including failures. Concurrent close calls share one cleanup promise, preventing an old close from releasing a newly opened adapter's lock. No lock file is deleted and no stale-lock stealing occurs.

This is the accepted single-process/exclusively controlled directory pattern, not a cross-process OS lock. Local filesystem administrators or concurrent external processes are outside its trusted local boundary. Fsync evidence is bounded by the local filesystem, OS and storage device. New-file directory fsync runs where supported outside Windows; Windows directory-entry/power-loss persistence is not established. A same-device local journal does not prove a separately hosted failure domain, backup lineage, rollback protection against whole-file historical replacement, hosted restore or remote erasure. Ordinary detectable corrupt tails are quarantined; no complete-prefix rollback detection is claimed without independent primary coverage. Strings in JavaScript cannot be reliably zeroized; copied key and plaintext byte buffers are cleared where available. Key destruction must be implemented outside recoverable content backups, reconciled with independent tombstones before exposure; this adapter does not implement deletion or choose retention policy.
