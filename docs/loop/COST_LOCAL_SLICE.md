## What is represented

The live request is always a synthetic unsettled fixture. Capture records acknowledge immutable metadata for actual terminal local mock-generation attempts, including failed, unsupported, cancelled and uncertain states. Unknown usage and charges remain unknown. Cancel-before-start has no fabricated dispatch attempt. Provider latency is not labour. Invented estimates use integer USD microcurrency; one million microUSD is one dollar. The toy rate of 3/7 microUSD per input/output token is fictional and is not a provider-price recommendation.

Corrections append immutable successors. Only the current leaf contributes to subtotals; the original entry remains inspectable. Known synthetic zero differs from unknown. Unpaid minutes remain separate from cash and have no invented wage valuation. Missing expected cash sources and work stages remain visible, so a known subtotal cannot masquerade as a complete cost.

The separate `comparison-v1` fixture has G1 (fictional settled), G2/G3 (fictional new) and one I1 reusable-pattern investment stored once. G2/G3 reference I1. Scenario ordinary costs and investment are added once. Allocating I1 over the closed fictional reference population does not add new expense. Its denominator is two fictional references, sample sizes are one fictional settled and two fictional new games, delivered referencing count is zero and actual reuse share is unavailable. An allocated comparison is not first-game all-in. No delivery-count input exists; with N=0, cost per delivered game is undefined.

## Boundaries and durability

The optional private founder cost routes use the existing real local founder identity/session issuer, active TEST-v1 consent, current child profile and accepted queue scope. They expose opaque metadata and fictional costs, never the question, draft, prompt, content digest, contact details or child profile text. Generation owns content validation. Explicit terminal job reads run outside cost transactions and the global queue serializer; queued/running jobs are not read or recovered by cost. Actual generation, review, auth, consent, profile, request, receipt, entitlement, publication, assignment and delivery rows must remain unchanged during cost-only calls.

A command first reserves an immutable sealed intent. It then appends to a separate authenticated encrypted cost journal outside database locks. Current source and authority are rechecked before effects and acknowledgement are committed atomically. Intent or journal presence alone is not a saved cost. An outage retains the exact original command for explicit recovery. Same-key replay does not charge twice. Source changes fence stale unacknowledged intent; retirement of absent/fenced keys prevents a late original from appearing. Another current founder can supersede a demoted actor's pending intent without reviving it after restoration. Current consent withdrawal closes ordinary reads and recovery.

The cost journal has separate domain keys and an authenticated namespace marker, using accepted queue encryption/hash-chain/fsync mechanics. Rejected wrong-key, foreign-domain or replacement-store adoption must preserve existing evidence. A used journal is not accepted with an initialized empty primary. This is local synthetic durability, not proof of hosted independent storage or production disaster recovery.

## Local operator flow and verification status

The optional local founder screen, strict client and private host integration are implemented in this candidate. Open the local founder workspace and choose the cost workbench. Select an accepted invented request; copy the matching job ID from the mock-generation record when capturing an eligible attempt. Its cost projection exposes eligible attempt IDs, not an uncaptured attempt-to-job map. This manual pairing is a bounded operator limitation; the server validates the exact pair.

Enter invented token/cash estimates or explicitly unknown values, record unpaid work under direct or fictional investment owners, and inspect immutable correction history. Lost replies retain the original operation; use explicit retry/recovery and dismiss only a durable absent/fenced result. Reload recovery without the original envelope deliberately avoids an exact Saved claim. The source-bound controller checks, native browser observations, attributed Claude verdict and partial acceptance receipt determine technical acceptance; this document alone claims none of those outcomes.

Authoritative implementation scope is ten application files plus the slice report and attributed feature-review records. Tests use invented disposable households, actual local auth/consent/setup/queue/mock-generation integrations, isolated journals and real HTTP cookies. The root independent probe computes its own arithmetic and hashes every complete non-cost public table before/after every guarded call. Browser tests and native observations must additionally verify recovery, clearing of held private responses, phone/zoom/keyboard behavior and input preservation. Preserve all previous-generation and review limitations; this slice does not repair reconsent profile adoption, actual provider readiness or public release gates.
