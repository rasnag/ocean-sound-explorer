# CODEX-07-A synthetic play service contract

Draft v1, 2026-11-11. This is application implementation for review, not an accepted card or production service.

Authority: engineering architecture v1.2, APPROVAL-004, SHA-256 `02adc2e0bf0910092f0888a126cdebe98adc35a177679bf124e0e79393532b79`; CODEX-00-B contracts1.1.1, wire1.1.0; authorized CODEX-07-A approved-copy blob `c40becc33e8f92a2418adf7e662c24b42ea79fd1`. Applicable interfaces are WM-06's deterministic transition engine and WM-07 StartPlay/CommitAction/ResumePlay. ADR-E01/E02/E05, the common household-first lock hierarchy, play consistency and v1.2 recovery invariants govern. No independent module architecture is introduced.

The synchronous `createSyntheticPlayService({db,env,catalog,journal,clock=Date.now})` returns async `start`, `commit`, `resume`, `reconcile` and synchronous `health`. Configuration must pass existing `resolveLoopConfig` with exact local-synthetic mode. The journal must be a branded instance from the actual filesystem factory; method-shaped callbacks cannot confirm durability. Real PGlite query/transaction support is required. No database module enters a client import.

Scope is the exact trusted object `{household_id,child_id,assignment_id,play_id,revision_id,consent_epoch}`. IDs are lowercase UUID strings; epoch is a positive safe integer. HTTP authority comes only from an immutable copied developer capability map. These capabilities do not establish verified adult or parent identity. Founder login grants no play authority. Every call, including duplicates, rechecks current latest active consent, child/request/revision/publication/assignment relationships, and pinned play epoch.

Catalogue entries are exactly `{household_id,revision_id,spec,starting_path,starting_reason}`. Entries are copied and recursively frozen. Complete adventure validation uses existing `validateAdventure`/`validateAssistedAdventure`; transitions and restoration use actual `createPlayer`/`createAssistedPlayer`. Relational published rows remain synthetic scaffolding and confer no human review/content approval. Metadata pins canonical full-spec SHA256, versions, scope, original epoch and explicitly human-selected synthetic starting path/reason. Catalogue changes fail closed.

Start input is exactly `{contract_version:'1.1.0',command_id,play_id,consent_epoch,revision_id,pattern_version:'fixture-1',engine_version}`. It creates sequence0/event0 with an actual engine snapshot and no events. Existing seed/uninitialized plays cannot be reset or adopted. Start duplicates preserve their original receipt. Resume input is exactly `{play_id,revision_id,consent_epoch}`. Commit accepts exact existing play_action1.1.0 envelopes and only actions supported by the pinned actual engine. Browser spec, outcome, timestamp, scope, extra fields or unsupported actions fail without effects.

Each primary operation owns one real outer transaction. Lock order is household/latest consent, request, revision, assignment, play. Unused entitlement/capacity/job levels are skipped. The process-local queue serializes PGlite operations across service instances; SQL locks still establish the withdrawal boundary. Multi-host operation is unproven and unsupported. A write committed before withdrawal remains a primary fact. Confirmation after withdrawal cannot expose its private checkpoint. Historical accepted envelopes replay with their original epoch; a caller must independently pass both the active latest epoch and original pinned epoch. Continuation across epoch changes needs separate lifecycle integration.

Action identity and canonical scope/command SHA256 dedupe precede sequence CAS. Same successful key with changed input conflicts; identical retries return the original checkpoint even after newer actions. Distinct stale writers conflict. Configure creates no trial. Test references exactly the current committed Predict and Configure; trusted engine dispatch determines the outcome. Compare must reference two actual trials of that play. All successful gameplay writes use `tx.query`, permitting real SQL boundary failure injection.

One action creates one existing play_events row containing the exact typed batch `{events:[...]}`. Existing action and sequence unique constraints remain intact. Action sequence and event sequence are distinct: Predict, Configure, Test give action3/event4. Events include contract, kind, deterministic action/index event ID, play/action IDs, authoritative action/event cursors, server UTC whole-second `server_at`, revision/pattern pins and `source:'server_observation'`.

The checkpoint is exactly `{checkpoint_id,last_action_sequence,last_event_sequence,state}`. State deep-equals the actual engine snapshot, including its pins, references and retained tries. Engine1 does not gain invented assistance fields.

The primary transaction atomically writes command/canonical result, event batch, checkpoint, authoritative play sequence and canonical pending journal intent. Its predetermined result is a candidate only. SQL `ack_state='pending'` means PENDING DURABILITY, even though the stored candidate's eventual wire status is acknowledged. Candidate Test batches already contain test_resolved/progress_saved to keep the whole candidate atomic. **No pending result or response exposes those events, its checkpoint or an older checkpoint. Future timeline projections must join the owning command's acknowledged marker before presenting progress_saved as fact.**

After primary commit, with no SQL transaction held, journal append validates a synthetic record, writes a checksum/length-framed canonical UTF8 JSON record to `play-journal.log`, calls actual FileHandle.sync, and reads/verifies the record. The service verifies returned reference and body, then reauthorizes under SQL locks before setting only the acknowledgement marker. No second gameplay effect occurs. Record shape is exactly `{version:1,synthetic_only:true,record_id,household_id,play_id,primary_commit_id,command_digest,result}`. The stable reference is `local-fsync:<record_id>`.

Acknowledged results are exactly `{status:'acknowledged',mode:'local-synthetic',acknowledgement_scope:'single-host-process-recovery-only',production_ready:false,play_id,action_id,primary_commit_id,durability_ref,checkpoint,events}`; Start has action_id null. Returned values are defensive copies. Primary commit plus journal or confirmation failure returns retryable_unacknowledged with stable play/action/primary IDs and no checkpoint/events. Exact retry or trusted `reconcile(scope)` backfills the original record and marker without adding trials/events. Resume never backfills silently: current pending state returns503/pending without data. Missing/mismatched acknowledged journal evidence is recovery_required, never an older save.

Per-play pending blocks new commands on that play. Actual journal failure additionally sets visible `health():{state:'journal_unavailable'}` and closes new writes. Successful backfill restores healthy state. A different withdrawn play's pending acknowledgement does not itself mark journal failure or prevent unrelated plays. Reconcile is server-only and has no HTTP/admin endpoint.

Resume reconstructs the complete original command chain from sequence0 and checks every canonical digest, full candidate result, typed event batch, event cursor, actual checkpoint and authoritative session sequence. Unknown/corrupt history fails closed, with scoped in-process quarantine permitted. It never resets or repairs gameplay from guesses. Acknowledged journal reads verify the complete file framing/checksum history, not an in-memory success flag.

Journal directories must already exist, be developer-owned and exclusively used for synthetic records. The adapter rejects path redirection, symlinks, nonregular/hardlinked log files and replacement of opened paths. Unix ownership/writable-mode checks apply where available; Windows ACL administration remains the developer's responsibility. Concurrent journal opens are unsupported; the factory rejects duplicate same-process opens. Reopen after close or killed writer verifies every complete frame. Truncation/checksum corruption fails with recovery_required and preserves the bytes for investigation. Partial writes poison the adapter; no acknowledged tail is silently discarded. The optional exact trusted `testHooks:{beforeAppend:async(record)=>void}` runs before new record writes with a defensive copy; return values are ignored. Hooks cannot replace append, sync or read and are never HTTP inputs.

The HTTP factory returns a real node:http server, requires explicit127.0.0.1 binding, accepts only POST /play/start, /play/action, /play/resume, and accepts bearer-header capabilities only. Actual Host port and absent-or-same-origin Origin are enforced. Forwarded, identity, cookie, duplicate authorization, query credentials and unknown routes are rejected. JSON/body/header bounds are8KiB and timeouts10seconds. Responses are no-store, nosniff, no-referrer, CSP default-src none, with no CORS. Statuses: success200, invalid400, credentials401/403, scope403, conflict409, pending/recovery503. Exceptions and credentials are never logged or reflected.

This adapter is plaintext synthetic local evidence on one host. File sync/close and process-reopen evidence do not establish host-loss, power-loss, independent production failure domains, encrypted recovery, deletion, revocation restore or full-database recovery. Those remain00-F/10/13 gated. Production privacy, provider, offer, capacity, content review and release gates remain open.
